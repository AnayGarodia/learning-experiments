# Prior-art sweep 4 (2026-09-09): retrofit memory layers, hash routing, associative-memory capacity, load balancing

Retrofit recipe that exists (2605.03229, UMich, May-Jun 2026; Qwen2.5-0.5B-Instruct, d=896): additive memory `h + alpha*mem(h)` (alpha init 0.01) at layers {6,12,18}, nk=128 per half-key (16,384 slots/layer), 4 heads, k=16, key dim 256; healed 2 epochs on 50k OpenAssistant responses (memory params only); then sparse finetuning: T=512 rows per layer per step, SGD lr 5e-4; LoRA r16 2e-4; full FT 1e-5. Replacement variant is dominated (+26% WikiText PPL, -5 to -8 pp TriviaQA); additive keeps base within noise. Total memory 49k slots. NO scaling-with-M data anywhere in this lineage.
Meta 2510.15103 (1.3B pretrained WITH memory, layer 12 of 22, 1M slots, k=32, 4 heads, value dim 1024): TF-IDF slot scoring vs DCLM background, top-t rows (t=500 facts / 10k docs) get gradient; SGD lr 2-5 on memory ("switching to SGD further decreased forgetting"); NQ F1 drop 11% vs 71% LoRA vs 89% full FT.
Meta 2412.09764: product keys 2^10 half-keys -> 1M values; key dim = d/2; placement {4,12,20} best of 3-layer options; key-usage bias noticed, unsolved (random extra pairs, softmax sink: inconsistent).
Hash Layers 2106.04426: fixed random routing = balanced hash = learned Switch quality at 64 experts; no aux loss; hash loses with many experts (redundant experts).
Capacity: Kanerva SDM linear in number of locations, independent of dimension (Keeler 1988); ~0.1M patterns before crosstalk. Dense associative memory exponential in d (Krotov-Hopfield, Ramsauer 2008.02217): property of dense keys, not of fixed top-k slot memory. Bricken 2303.11934: SDM as top-k MLP continually learns without replay if dead neurons are handled (no momentum on inactive units).
Utilization collapse: Lample 1907.05242 at 1M keys: query BatchNorm raises usage 25.8% -> 80.3%; usage tracks heads x k. FwPKM 2601.00671: marginal-entropy address loss lifts coverage 7-12% -> 16-32%. Load balance: Switch aux loss; DeepSeek loss-free bias (2408.15664, u=1e-3 on top-k scores only); Demons 2501.11873: micro-batch balancing kills specialization, use global-batch stats. No paper applies load balancing to product-key memories or measures balance in a CL memory layer.

Implications: report usage + KL-from-uniform with every forgetting curve; query-norm + >=4 heads before any loss; balance READS (loss-free bias), keep WRITES narrow; augment, do not replace; use SGD (not Adam) on values; keep cumulative written rows well below M; the M-sweep for forgetting is new.
